# mailproxy - проксирующий почтовый сервер

> [English version](README.md)

Комплект развертывания на Docker Compose, предназначенный для локального получения и кеширования почты с реальных почтовых серверов (POP3, IMAP), и раздачи ее по IMAP внутреннему набору пользователей, а также приему от них писем через SMTP и отправке через реальные почтовые сервера.

## Случаи использования

У небольшой организации, команды или индивидуального пользователя имеется один или несколько почтовых ящиков, размещенных на общественных или платных сервисах. Необходимо предоставить доступ одному или нескольким внутренним пользователям, с учетом следующих возможных задач:

- иметь возможность подключать или отключать отдельных пользователей;
- не выдавать пользователям пароль от реальных почтовых ящиков;
- организовать единую точку управления учетными записями почты;
- организовать единую точку фильтрации / сортировки (вручную, силами кого-то из пользователей, или, например, подключив внешний клиент IMAP);
- свести хранение писем в одно место на сервере, с возможностью создания регулярных бекапов;
- обеспечить доступ к почте при изоляции доступа к Интернету.
- кешировать письма локально, но удалять на реальном сервере - сразу, либо по истечению срока, определенного в настройках учетной записи (в целях безопасности, или из соображений не занимать свободное место у хостера, которое может быть ограничено условиями использования).

Для этого, с использованием конфигурационных файлов (графический интерфейс управления не предусмотрен), прописываются внешние почтовые ящики (с реальными адресами, серверами, логинами и паролями), и пользователи, которые получают к ним доступ. 

К каждому ящику может быть открыт один или несколько пользователей. 

```
пользователь 1 --\
пользователь 2 --+---  почтовый ящик 1 (mailproxy) --- почтовый ящик 1 (gmail.com)
пользователь 3 --/

пользователь 4 --\
пользователь 5 --+---  почтовый ящик 2 (mailproxy) --- почтовый ящик 2 (yourcompany.com)
```

С использованием имен и паролей этих пользователей настраиваются внешние почтовые клиенты (Outlook, Thunderbird и др.). Возможно развертывание web-клиента (Roundcube). 

Прокси-сервер регулярно опрашивает реальные почтовые серверы, собирает почту в локальные копии ящиков, предоставляя пользователям доступ через их почтовые клиенты или Roundcube, а также принимает письма для пересылки через реальные почтовые серверы.

## Компоненты

| Сервис | Образ | Роль |
|---|---|---|
| **fetcher** | Python 3.11 | Опрашивает POP3/IMAP, доставляет письма в Maildir, генерирует карты учётных данных для Dovecot и Postfix |
| **dovecot** | Debian / Dovecot 2.4 | IMAP-сервер (порты 143 / 993) |
| **postfix** | Debian / Postfix 3.x | SMTP-ретранслятор с аутентификацией отправителя (порт 587) |
| **roundcube** *(опционально)* | roundcube/roundcubemail 1.6 | Веб-интерфейс, включается через `ENABLE_ROUNDCUBE=true` файла .env |

## Установка
```sh
# 0. Установить необходимое ПО
apt install git docker.io docker-compose-plugin


# 1. Развернуть репозиторий (в /opt/mailproxy)
cd /opt
git clone https://github.com/stvorl/mailproxy.git
cd mailproxy
chmod +x mpcontrol

# 2. Определиться, создается ли новое развертывание 2A, 
# или восстанавливается копия 2B

# 2A. Создать конфигурационные файлы (accounts.yml и .env) из шаблонов
./mpcontrol init

# Заполнить настройки и учётные данные согласно указаниям в комментариях файлов.

nano accounts.yml
# В общих чертах - создать записи для почтовых ящиков, указать логины, пароли, способы подключения к реальным серверам, интервал хранения, интервал опроса реального ящика. Добавить внутренних пользователей.

nano .env
# В общих чертах - Указать, запускать ли ROUNDCUBE (Web-интерфейс почт), и настроить, на каких портах должны работать наши серверы IMAP, SMTP, и должны ли они отвечать в сеть, или работать только локально.


# 2B. Если переносите с другой машины — использовать `./mpcontrol import <ваш файл бекапа>`: это восстановит logs, certs, maildata, rcdata, accounts.yml, .env
./mpcontrol import backup.tgz # Ваш файл бекапа


# 3. Запустить.
./mpcontrol up


# 4. Проверить работоспособность. 
# 4.1 Посмотреть логи в подкаталоге logs, а также с помощью:
./mpcontrol logs

# 4.2 Убедиться, что контейнеры запустились и открыли запрошенные порты.
docker compose ps

# 4.3. Открыть roundcube с помощью браузера и/или настроить почтовый клиент (Thunderbird, Outlook и т.п.), протестировав работу внутренних пользователей.
```


## Структура проекта

```
.env                  # конфигурация сервисов
mpcontrol             # скрипт управления
accounts.yml          # учётные данные — не коммитится (в .gitignore)
accounts.example.yml  # аннотированный шаблон
certs/                # сертификаты для серверов IMAP, SMTP
docker/
  fetcher/            # сервис загрузчика почты
  dovecot/            # сервис Dovecot
  postfix/            # сервис Postfix
  roundcube/          # сервис Roundcube
    plugins/
      fix_identity/   # плагин: редирект алиасов + правка поля From
logs/                 # логи контейнеров на хосте — не коммитится
maildata/             # Maildirs — не коммитится
rcdata/               # SQLite-база Roundcube — не коммитится
```

## accounts.yml

Все почтовые аккаунты, которые проксирует данный инструмент, описываются в `accounts.yml`. Fetcher перечитывает файл при каждом цикле опроса — перезапуск не нужен.

### Один логин (простая форма)

```yaml
global:
  default_fetch_interval: 15   # минуты

accounts:
  - address: alice@example.com

    inbound:                     # забрать почту с удалённого POP3
      host: pop.example.com
      port: 995
      proto: pop3
      tls: true
      user: alice@example.com
      pass: remote_password
      keep_remote: false         # false — удалять сразу; true — хранить вечно; 7d — 7 дней

    outbound:                    # SMTP-ретранслятор для отправки
      host: smtp.example.com
      port: 587
      tls: true
      user: alice@example.com
      pass: smtp_password

    local:                       # IMAP-учётные данные (независимы от удалённых)
      mailbox: alice@example.com # Внутренний логин доступа к IMAP/SMTP
      password: local_password   # Внутренний пароль доступа к IMAP/SMTP
```

Директивы `local.mailbox` и `local.password` являются обязательными.

### Несколько логинов для одного ящика

Несколько пользователей могут одновременно пользоваться одним и тем же ящиком — общий список писем и папок, общая адресная книга в Roundcube. При этом у них будут разные логины и пароли, и их можно будет избирательно отключить при необходимости.

```yaml
    # секции inbound и outbound — как выше
    local:
      mailbox: bob@example.org
      password: default_pass
      logins:
        - user: bob
          password: bobs_pass
        - user: carol
          password: carols_pass
```

Директивы `local.mailbox` и `local.password` всё еще являются обязательными.

Когда задан `logins:`, вход под именем `bob` или `carol` автоматически перенаправляется на канонический аккаунт `bob@example.org` — оба видят одни и те же папки, письма и контакты. При этом, основной пароль (`local.password: default_pass`) продолжает работать и допускать в учетную запись, но его, в таком случае, никому сообщать не следует. При необходимости, можно отключить `bob` или `carol`, или добавить новых пользователей.

### keep_remote — сколько держать письма на реальном сервере до удаления

| Значение | Поведение |
|---|---|
| `false` или `0` | Удалить с сервера сразу после скачивания (по умолчанию) |
| `true` | Оставить на сервере навсегда |
| `10m` | Удалить через 10 минут |
| `12h` | Удалить через 12 часов |
| `7d` или `7D` | Удалить через 7 дней |
| `3M` | Удалить через 3 месяца (~90 дней) |
| `30s` | Удалить через 30 секунд |

Письма скачиваются **только один раз**. Состояние хранится в файле `.fetch_state_*.json` в директории ящика.

### fetch_depth — ограничение глубины поиска (только IMAP)

Если `keep_remote: true` и на реальном сервере тысячи писем, каждый цикл опроса запрашивает полный список. `fetch_depth` заставляет фетчер использовать `SEARCH SINCE <дата>` вместо `SEARCH ALL`, что резко сокращает передаваемый список UID.

```yaml
    inbound:
      proto: imap
      keep_remote: true
      fetch_depth: 30d   # искать только письма за последние 30 дней
```

Принимает те же суффиксы, что и `keep_remote`: `30d`, `3M`, `12h` и т.д. По умолчанию: без ограничений.

**Взаимодействие с `keep_remote` timedelta:** если `keep_remote` тоже задан как длительность, эффективная глубина автоматически расширяется до `keep_remote + 10 × fetch_interval`. Это гарантирует, что письма вблизи срока удаления остаются видны фетчеру достаточно долго, чтобы быть удалёнными. При автоматической корректировке в лог выводится сообщение.

**Взаимодействие с `keep_remote: false`:** фетчер загружает, сохраняет и удаляет с реального сервера только письма в пределах `fetch_depth`. Письма старше не сохраняются и не удаляются.

Для POP3 параметр `fetch_depth` не работает — протокол всегда возвращает полный список писем, что для почтовых ящиков с большим количеством неудалённых писем может приводить к замедлению получения новых писем. В этом случае целесообразнее воспользоваться IMAP с указанием `fetch_depth`.

### IMAP-источник

Если провайдер не поддерживает POP3 или нужно забирать письма из конкретной папки — используйте `proto: imap`:

```yaml
    inbound:
      host: imap.example.com
      port: 993
      proto: imap
      tls: true
      folder: INBOX               # опционально; по умолчанию INBOX; через запятую, например "INBOX, SPAM"
      user: charlie@example.com
      pass: remote_password
      keep_remote: 5d             # удалять через 5 дней
```

## Настройка (.env)

Файл `.env` содержит параметры работы наших сервисов в сети.

### Roundcube

Опциональный почтовый web-клиент, который может быть развернут поверх IMAP/SMTP серверов комплекта. При его использовании можно отключить внешний доступ к IMAP/SMTP серверам, и, тем самым, воспретить использование сторонних клиентов.

Установите `ENABLE_ROUNDCUBE=true` в `.env`, чтобы включить Roundcube в стек. 
Roundcube доступен, по умолчанию, по адресу **http://<имя узла>:8080**.

```sh
ENABLE_ROUNDCUBE=true     # раскомментировать, чтобы включить веб-интерфейс

ROUNDCUBE_LISTEN=0.0.0.0  # Адрес, на котором слушает веб-интерфейс (0.0.0.0 - на всех интерфейсах данного узла, 127.0.0.1 - на внутреннем интерфейсе)
ROUNDCUBE_PORT=8080       # HTTP-порт.
ROUNDCUBE_TITLE=Roundcube # Заголовок вкладки браузера (опционально)
```

### IMAP-сервер (Dovecot)

IMAP4-сервер, предназначенный для доступа наших пользователей к почтовому ящику.

Два порта: **143** (plain/STARTTLS) и **993** (IMAPS). Адрес прослушивания и уровень TLS настраиваются независимо.

| `IMAP_TLS` | Поведение |
|---|---|
| `1` | Нешифрованное соединение, STARTTLS не предлагается |
| `2` | STARTTLS доступен (по запросу клиента) |
| `3` | STARTTLS обязателен + доступен порт 993 (IMAPS) |

Рекомендуемые комбинации:

| Сценарий | `IMAP_LISTEN` | `IMAPS_LISTEN` | `IMAP_TLS` |
|---|---|---|---|
| Только локально, для Roundcube | `127.0.0.1` | `127.0.0.1` | `1` |
| Локальная сеть, STARTTLS + IMAPS | `0.0.0.0` | `0.0.0.0` | `2` |
| Локальная или глобальная сеть, только IMAPS | `127.0.0.1` | `0.0.0.0` | `3` |

```sh
IMAP_LISTEN=127.0.0.1
IMAP_PORT=143
IMAPS_LISTEN=0.0.0.0
IMAPS_PORT=993
IMAP_TLS=3
```

### SMTP-сервер (Postfix)

Прокси-сервер исходящей почты, пересылающий сообщения на реальные серверы.

Один порт **587** (submission). Аналогичные параметры:

| `SMTP_TLS` | Поведение |
|---|---|
| `1` | Без шифрования |
| `2` | STARTTLS доступен |
| `3` | STARTTLS обязателен |

```sh
SMTP_LISTEN=0.0.0.0
SMTP_PORT=587
SMTP_TLS=3
```

## Управление контейнерами

Управление необходимо осуществлять с помощью скрипта `mpcontrol`.

| Команда | Описание |
|---|---|
| `./mpcontrol init` | Создать рабочие конфигурации из шаблонов, подготовить компоненты к первому запуску |
| `./mpcontrol up` | Собрать образы и запустить все сервисы |
| `./mpcontrol down` | Остановить все сервисы |
| `./mpcontrol restart` | `down` + `up` |
| `./mpcontrol rebuild` | Принудительно пересобрать образы без кэша Docker (после обновления базовых образов) |
| `./mpcontrol logs` | Следить за логами всех сервисов |
| `./mpcontrol export <имя>` | Остановить сервисы и упаковать `maildata/`, `rcdata/`, `certs/`, `logs/`, `accounts.yml`, `.env` в архив |
| `./mpcontrol import <имя>` | Распаковать архив в директорию проекта (сервисы не запускаются) |
| `./mpcontrol clean` | Остановить сервисы и **безвозвратно удалить** все данные (`maildata/`, `rcdata/`, `certs/`, `accounts.yml`, `.env`). Требует ввода `YES` для подтверждения. |

## Безопасность

- По умолчанию все сервисы, кроме RoundCube, слушают только `127.0.0.1`. Для доступа по сети задайте соответствующие параметры в `.env`.
- При внешнем доступе установите `IMAP_TLS=3` и `SMTP_TLS=3` для обязательного TLS. Самоподписанный сертификат (и частный ключ к нему) генерируются автоматически в `certs/` при первом запуске. При необходимости замените на реальный сертификат.
- Для резервного копирования используйте `./mpcontrol export` либо копируйте каталоги `maildata/`, `rcdata/`, `logs/`, `certs/`, файлы `.env`, `accounts.yml` — например, с помощью borg, restic и т.п. Всё остальное восстанавливается через `git clone`.

## Миграция

Для переноса архива почты, настроенных учетных записей, логов, сертификатов и параметров серверов, необходимо:

### На исходной машине:
```sh
./mpcontrol export backup.tgz
# переписать файл на целевую машину.
```

### На целевой машине
Выполнить шаги 0-1, 2b, 3-4 из раздела "Установка".

## Обновление версии

```sh
# 1. Сохранить резервную копию (на всякий случай)
./mpcontrol export backup-before-upgrade.tgz

# 2. Остановить сервисы
./mpcontrol down

# 3. Получить обновления из репозитория
git pull

# 4. Пересобрать образы без кэша
./mpcontrol rebuild

# 5. Запустить
./mpcontrol up
```

После обновления проверьте логи на наличие ошибок: `./mpcontrol logs`.

## Производительность

Каталоги /maildata, /rcdata, /logs, содержащие критичные для производительности данные, целесообразно перенести на предназначенные для этого физические или логические тома, вернув назад symlink-и.
